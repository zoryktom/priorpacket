# Health-System Evaluation Guide

PriorPacket is easiest to understand as a pre-submission proof checker.

It answers one operational question:

> Is this prior authorization packet ready to submit, or is required proof missing?

## What to evaluate in 30 minutes

1. Run the product validation suite.
2. Open the local review console.
3. Select each synthetic scenario and inspect the evidence packet.
4. Run the batch analyzer and inspect the CSV gap report.
5. Review the audit manifest and SHA-256 hashes generated by a single packet run.

## Commands

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .

priorpacket validate-policy --policy examples/policies/knee_mri_policy.json

priorpacket validate-product \
  --manifest examples/cases/manifest.json \
  --out reports/validation

priorpacket batch-analyze \
  --policy examples/policies/knee_mri_policy.json \
  --bundles examples/cases/fhir \
  --service-code 73721 \
  --out reports/batch

priorpacket serve
```

Open `http://127.0.0.1:8787` for the local review console.

## What a buyer should look for

- The tool separates ready packets from packets missing proof.
- Every criterion maps to inspectable FHIR evidence.
- Every missing item turns into a staff action.
- Batch output shows where rework is coming from.
- Validation cases are reproducible and versioned.
- No external service is required for the open-source core.

## What this is not

PriorPacket does not determine coverage, make treatment recommendations, guarantee approval, or submit requests to payers. It prepares a defensible evidence packet for qualified staff review.

## Pilot metric

The first pilot should measure:

`percent of requests with missing proof found before submission`

Secondary metrics:

- Staff minutes per packet.
- Requests for additional information.
- Medical-necessity documentation denials.
- Rework by payer and CPT code.
- Staff acceptance rate for each missing-proof flag.
